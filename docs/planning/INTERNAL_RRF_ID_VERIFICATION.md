## Summary

The Internal RRF ID system has been verified and is working correctly. The system uses three distinct ID types:

1. **Internal Database ID (`id`)** - Auto-incremented primary key
2. **RRF Number (`rrf_number`)** - User-facing display ID (e.g., "RRF-013")
3. **Internal RRF Number (`internal_rrf_no`)** - Auto-generated ONLY for bench-filled positions (e.g., "RRF-INT-001")

## Database Structure ✅

### Table: `rrfs`

| Column | Type | Constraints | Purpose |
|--------|------|-------------|---------|
| `id` | integer | PRIMARY KEY, AUTO INCREMENT | Internal database identifier |
| `rrf_number` | varchar(20) | UNIQUE, NULLABLE | User-facing RRF ID (e.g., "RRF-013") |
| `internal_rrf_no` | varchar(50) | UNIQUE, NULLABLE | Auto-generated for bench fills (e.g., "RRF-INT-001") |

### Auto-Generation

**Internal ID (`id`)**:
```sql
Default: nextval('rrfs_id_seq'::regclass)
Current Sequence: 51
Status: ✅ Working
```

**Internal RRF No (`internal_rrf_no`)**:
- Generated by: `generateInternalRrfNumber()` in backend service
- Format: `RRF-INT-XXX` (3-digit padding)
- Trigger: Only when PMO fills position from bench
- Example: RRF-INT-001, RRF-INT-002, RRF-INT-003

## Backend Implementation ✅

### Entity Definition
**File:** `rrf-portal-backend/src/rrf/entities/rrf.entity.ts`

```typescript
@PrimaryGeneratedColumn()
id: number;  // Internal database ID

@Column({ name: 'rrf_number', unique: true, length: 20, nullable: true })
rrfNumber: string;  // User-facing RRF ID

@Column({ name: 'internal_rrf_no', type: 'varchar', length: 50, nullable: true, unique: true })
internalRrfNo: string;  // Auto-generated for bench fills
```

### Service: Fill By Bench
**File:** `rrf-portal-backend/src/rrf/rrf.service.ts`

**Method:** `fillByBench(id: number, userId: number, candidateName?: string, joiningDate?: string)`

**Process:**
1. Validates RRF status (APPROVED or IN_PROGRESS)
2. Generates unique Internal RRF Number using `generateInternalRrfNumber()`
3. Updates RRF with optimized query:
   - Sets `status` to CLOSED
   - Sets `closureStatus` to 'filled-by-bench'
   - Sets `internalRrfNo` to generated value (e.g., RRF-INT-001)
   - Saves candidate name and joining date
   - Appends status history

**Format:** `RRF-INT-XXX`
- Queries max existing internal RRF number
- Increments by 1
- Pads to 3 digits
- Checks for duplicates and retries if needed

- Reports on internal placements

**Display ONLY for closed-by-bench status**

## Post-Close Behavior ✅

### Normal Closure (HR Fills Position)
1. PMO opens position → Status: IN_PROGRESS
2. HR finds candidate → Closes RRF
3. System sets:
   - `status` = CLOSED
   - `closureStatus` = 'Position Filled'
   - `candidate_name` = Candidate name
   - `internal_rrf_no` = **NULL** (not from bench)

**Display:**
- RRF ID: "RRF-013"
- Internal RRF No: (not shown)

---

### Bench Fill Closure (PMO Fills from Bench)
1. PMO opens position → Status: IN_PROGRESS (or APPROVED)
2. PMO finds internal resource → Clicks "Fill from Bench"
3. System sets:
   - `status` = CLOSED_BY_BENCH
   - `closureStatus` = 'filled-by-bench'
   - `candidate_name` = Candidate name
   - `internal_rrf_no` = **"RRF-INT-001"** (auto-generated)

**Display:**
- RRF ID: "RRF-009"
- Internal RRF No: **"RRF-INT-001"** (shown in purple)
